# Asset pipeline

Blender → GLB → Three.js. Every choice below was measured on this project's actual assets, not
inherited from general advice.

This document covers the 3D pipeline and the Blender-rendered DOM illustration extension. Generated
sound effects, music loops, audio loading policy and the full action audit live in
[AUDIO.md](AUDIO.md).

> **Corrected 2026-08-10.** An earlier version of this document told developers to set up a DRACO
> decoder in `public/draco/`. Measurement showed that to be **actively harmful** at this project's
> asset size — the decoder costs more than the compression saves. See "Mesh compression" below. The
> `DRACOLoader` import has since been **removed entirely** from `modelLoader.ts`: importing it caused
> Vite to emit 836 KB of decoder chunks into `dist/` for a feature nothing uses.

## The rule

**Nothing loads an asset by hardcoded URL.** Every asset is declared in
`apps/game/src/assets/manifests/core.manifest.ts` and fetched through `AssetLoader`. That is what
makes cache-busting, preloading and a CDN swap possible without touching gameplay code.

Audio follows the same catalog rule. `audio.manifest.ts` is spread into the core manifest;
generated files never bypass `AssetLoader`, and missing audio falls back instead of becoming a
critical scene error. DOM images resolve their `src` through `uiIcons.manifest.ts`.

## Source of truth

Art is generated by script, not hand-modelled. See
[ART_IMPLEMENTATION_GUIDE.md](ART_IMPLEMENTATION_GUIDE.md).

```
tools/blender/*.py  ──art:build──▶  art/source/farmrise_assets.blend   (editable master)
                                    apps/game/public/assets/models/*.glb (what ships)
                                    art/build_report.json               (tris + bytes)

art/source/farmrise_assets.blend ──art:ui-icons──▶ apps/game/public/assets/ui/icons/*.webp
                                                   art/ui_icon_report.json
```

`art/measure/` holds compression variants for benchmarking only and is gitignored.

## World texture compression: not applicable

There are **no sampled textures in the 3D world**. All world colour is in `COLOR_0` vertex
attributes against a single material. The DOM's transparent WebPs are ordinary browser images and
do not require a KTX2/Basis transcoder.

KTX2/Basis Universal was evaluated and rejected — not on merit, but because there is nothing for it
to compress. Adopting it would mean adding a transcoder (~250 KB) to decode zero textures.

**Revisit if** the project ever adopts hand-painted atlases (see improvement plan item 10). At that
point KTX2 becomes the right answer for a web target and the measurement should be redone.

## Mesh compression: measured, then rejected

Blender 5.2's glTF exporter ships both Draco and Meshopt, so both were benchmarked against the real
assets. What matters is **transport bytes after gzip, plus the decoder the browser must fetch** — a
comparison of raw payloads alone is misleading.

| Family | raw + gzip | Draco + gzip | Meshopt + gzip |
| --- | ---: | ---: | ---: |
| crops | 128,926 | 89,177 | 112,529 |
| buildings | 38,774 | 36,023 | 31,814 |
| animals | 19,103 | 14,764 | 23,554 |
| characters | 34,808 | 24,657 | 38,923 |
| props | 33,813 | 29,332 | 38,719 |
| ground | 3,182 | 3,160 | 2,881 |
| **Total** | **258,606** | **197,113** | **248,420** |

Add the decoder each option requires:

| Option | Transport | Decoder | **First load** |
| --- | ---: | ---: | ---: |
| **Plain GLB + gzip** | 258,606 | 0 | **258,606** |
| Meshopt + gzip | 248,420 | ~5,000 | **253,420** |
| Draco + gzip | 197,113 | ~230,000 | **427,113** |

### Decision: ship plain GLB with gzip/brotli. No mesh compression.

- **Draco is still worse than doing nothing.** Its decoder makes first load about 168 KB larger than
  plain GLB.
- **Meshopt now saves only about 5.2 KB (2%) after its decoder.** The authored set crossed the old
  1 MB / 200 KB revisit threshold, was remeasured, and still does not justify a runtime dependency
  and decode path. ADR 0015 records the revised decision.
- Vertex-colour meshes with no UVs and no tangents still gzip well: raw GLB compresses about 4×.

### Concrete triggers to revisit

Not "revisit later" — these are testable thresholds:

| Adopt | When |
| --- | --- |
| **Meshopt** | Measured first-load saving reaches at least 25 KB, or cold-load profiling shows model transfer is a user-visible bottleneck. Current net saving is about 5.2 KB. |
| **Draco** | Raw model payload > ~3.3 MB, where the saving finally exceeds the 230 KB decoder. |
| **KTX2** | The first sampled 3D-world texture ships. |

Re-run `npm run art:build`; `art/build_report.json` records raw and gzip bytes for every variant.

## LODs: not implemented, and deliberately so

At 13,241 triangles for the entire authored asset set, LODs would be optimisation without evidence.
The heaviest single asset is the 2,438-triangle farmer, still below its 2,600-triangle class budget.

**Revisit if** a profiling session shows geometry-bound frames on a target device. Three.js has no
built-in LOD authoring, so this would mean either `THREE.LOD` with script-generated decimations or
`gltfpack -si` — Blender's exporter already exposes gltfpack options.

## Loading

`AssetLoader` (`assets/loaders/AssetLoader.ts`):

- Caches by id and **de-duplicates concurrent requests** — several views want the same family.
- Reports **byte-weighted** progress from the manifest's `bytes` field, so the loading bar moves in
  proportion to work remaining rather than jumping in sixths.
- Honours an `AbortSignal`.
- `critical` failures propagate; `preload` failures are logged and swallowed.

`ModelLibrary` (`assets/registries/ModelLibrary.ts`) flattens loaded glTF scenes into a
name → `BufferGeometry` map and owns the single shared material. It hands out **geometry**, not
objects, because almost everything is drawn as an `InstancedMesh`.

### Graceful degradation is a requirement, not a nicety

Every view takes `ModelLibrary | null`. `FarmScene.#loadArt()` catches per-family failures and
returns `null` if nothing loaded. Consequences:

- A missing GLB shows placeholder primitives, not a black screen.
- The jsdom test suite runs with no art on disk and no network.
- A developer who has never run Blender can still `npm run dev`.

## Draw calls

Draw calls are proportional to distinct **meshes**, not to object count.

| Content | Draw calls |
| --- | --- |
| Plot beds (any number) | 1 |
| Crops | ≤ 12 (one per crop × stage in use) |
| Scatter grass + bushes | 2 |
| Chickens (any number) | 1 |
| Buildings | 1 per placed building |
| Ground, player, foxes | 1 each |

Buildings are the only unbatched category, because each has a distinct mesh and there are few of
them. If a player ever places fifty fences, that becomes the first thing to instance.

## Profiling: what has and has not been done

**Measured:** triangle counts and raw/gzip/Draco/Meshopt bytes per family
(`art/build_report.json`), bundle sizes from `vite build`, and a live starter view at 36 draw calls
and 72,694 rendered triangles. The complete 88-test Playwright matrix passes in desktop Chromium,
mobile Chromium, Firefox and WebKit.

**Not measured:** GPU memory, cold-cache load time, or sustained frame time on a physical mid-range
phone. The browser results are regression checks on one development machine, not a device-wide
performance claim.

Before shipping, run: Chrome DevTools performance trace on a mid-range Android device, `renderer.info`
draw-call and triangle counts at a full farm, and a cold-cache load-time measurement.

## Regression checks

| Check | Command | Enforces |
| --- | --- | --- |
| Triangle budgets | `npm run art:build` | Fails the build over budget |
| Unpainted faces | `npm run art:build` | Fails if any face has no palette colour |
| Datablock name collisions | `npm run art:build` / `art:review` | Prevents `.001` suffixes reaching the GLB |
| Palette contrast | `npm run art:check` | Findability ≥1.6:1, progression ≥1.5:1 |
| Stage mapping | `npm test` | Stage 4 ⇔ harvestable |
| Mesh names match code | `npm test` | `cropMeshName` format |
| Manifest model bytes | `npm test` | Shipped GLB sizes match `art/build_report.json` and `core.manifest.ts` |

## Troubleshooting

| Draco chunks in `dist/` | Something re-imported `DRACOLoader` | It is not needed; see ADR 0010 and the note at the top of `modelLoader.ts` |
| Review renders framed differently from the game | Camera constants drifted | `cameraFraming.test.ts` fails on this; fix `palette.py` or `sessionRules.ts` |

| Symptom | Cause | Fix |
| --- | --- | --- |
| Everything renders grey | Vertex colours lost — usually a topology op running before faces were painted | The build now fails instead; check the face colour layer in `buildlib.py` |
| Colours look washed out / milky | sRGB hex written into a linear buffer | Use `linear_rgba()`, never raw hex |
| Meshes named `SM_x.001` in the GLB | Orphaned datablocks from a previous build | `npm run art:build` purges them; do not save over the master by hand |
| Foliage invisible from one side | Material lost `doubleSided` | Leaves are single-sided geometry by design |
| `Model "..." is not in the library` | Renamed in `assets.py` without updating the view | Keep `BUILD_ORDER` and the view's mesh-name constants in step |
| Placeholder primitives in the browser | GLBs missing from `public/assets/models/` | `npm run art:build` |
